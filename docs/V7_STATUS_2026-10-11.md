## Bugs fixed this session (root cause of the "silent/hung" runs)
1. `model/training/consistency.py` — used `F.binary_cross_entropy` under AMP autocast (illegal,
   raises). The term needs both `cls_logits` + `seg_logits`, so it only ran from **stage 4** on;
   stages 1-3 trained fine, then stage 4 crashed. Replaced with the identical formula on clamped
   fp32 probs.
2. `model/training/dataset.py` — `(m == 255)` referenced `m` before it was bound => NameError on the
   combined `masks/{split}` layout (the layout the corpus actually uses). Surfaces as a DataLoader
   worker hang. Fixed with an explicit resize.

## ONNX + quantization (new, verified locally)
`model/training/export_onnx.py` now supports `--quant-mode {static,dynamic,both}`:
- FP32          10.0 MB, 25.9 ms (1-thread CPU)
- INT8 static    3.0 MB, 18.5 ms  <-- 1.4x faster, 3.3x smaller, <1% output diff vs fp32
- INT8 dynamic   2.8 MB, 91.4 ms  <-- SLOWER; do not use for latency (size only)
Static needs calibration data (`--calib-root`, uses the corpus train split).
Drivers (`smoke`/`train`/`plantseg`) now `pip install onnxruntime onnx` and pass
`--quant-mode both --calib-root DATA`. `NO_ORT=1` skips the install; `QUANT_MODE` overrides the mode.
Code dataset version pushed with these changes.

NOTE: the two kernels already RUNNING started before the quantization change, so *this* run's
export step will only emit FP32 (no INT8). Training itself is unaffected.
