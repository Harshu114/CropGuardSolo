# CropGuard v7 — PlantSeg + PlantDoc evaluation (2026-10-11)

Model: `model/weights/v7/best_stage5.pt` (and `best_stage5_calibrated.pt`, which
carries the fitted temperature). Nothing here is retrained — this evaluates the
checkpoint that already exists, on the two requested test sets.

Requested scope: **PlantSeg test + PlantDoc test only**, reporting classification
accuracy + per-class, segmentation IoU on the real lesion masks, and severity as
the computed lesion/leaf ratio. Detection numbers are included because the model
produces them, but they are not the headline.

---

## 0. The derive pipeline was broken — found by the overlay spot-check, fixed

The spot-check was run *before* trusting any number, exactly as asked. It caught
a real defect.

**Symptom.** For each of 50 random test images we measured how much of the
lesion mask falls inside the leaf mask. A lesion is part of a leaf, so this
should be 1.0. It was **0.62** (median over all 130 test images: 0.64;
**95/130 images below 0.90**).

**Consequence.** Severity is `lesion_px / leaf_px`. With the lesion partly
outside the leaf mask the denominator is too small, so severity was inflated —
worst case **4.04**, i.e. "the lesion is 4× the leaf", which is impossible. It
was silently clamped to 1.0, so every such image was labelled *severe*.

**Root cause.** `grabcut_leaf_mask` seeded GrabCut only from *green* pixels
(`g > r + 10 and g > b + 10`). Necrotic (brown/yellow) lesion tissue is not
green, so GrabCut classed it as background and the "leaf" came out missing the
diseased region — the one region severity depends on.

**Fix** (`data_pipeline/scripts/derive_dataset.py`):
1. seed the annotated lesion as GrabCut **certain-foreground** (`GC_FGD`), not
   just probable;
2. after component selection, **union the lesion back into the leaf mask**, so
   `lesion ⊆ leaf` holds by construction, independent of the leaf backend.

Also fixed in the same area: `releaf_split.py` read the JPEG with `cv2.imread`,
which applies EXIF rotation, while the derive wrote the masks against PIL's
(non-rotated) orientation — the two disagreed and produced transposed output.
The repair script now reads images with PIL, matching the derive.

| metric (test, n=130) | before | after |
|---|---|---|
| mean lesion-in-leaf | 0.589 | **1.000** |
| severity p50 / p95 / max | 0.010 / 0.082 / **4.04** | 0.011 / 0.171 / **0.976** |
| rect-likeness (1.0 = detection boxes) | 0.014 | 0.014 |
| images repaired | — | 129/130 (val 136/136, train 633/635) |

Rect-likeness 0.014 confirms these are **real polygon masks**, not filled
detection boxes — unlike `cropguard-corpus-claude`, whose masks were
pixel-identical to its boxes (see `docs/V7_DATA_AUDIT_2026-10-11.md`).

50 rendered overlays (image + lesion + leaf + severity + grade) are in
`~/tmp/cgcheck/` (`_contact_sheet.png` is the montage).

## 1. PlantSeg test (130 images, real lesion masks)

`model/training/eval_tta.py --arch v7 --ckpt best_stage5_calibrated.pt`

| metric | value |
|---|---|
| cls top-1 | **0.517** |
| cls macro-F1 | 0.326 |
| cls ECE (10-bin, temperature-scaled) | 0.103 |
| seg mIoU (lesion, real masks) | **0.010** |
| seg Dice | 0.020 |
| severity MAE | 0.864 |
| severity R² | −50.5 |
| mAP@0.5 (context only) | 0.000 |

Per-class F1 (support in the 130-image split):

| class | support | F1 |
|---|---|---|
| early_blight | 23 | 0.692 |
| late_blight | 26 | 0.696 |
| leaf_mold | 21 | 0.588 |
| septoria_leaf_spot | 18 | 0.556 |
| yellow_leaf_curl_virus | 8 | 0.571 |
| mosaic_virus | 14 | 0.333 |
| bacterial_spot | 10 | 0.154 |
| healthy / leaf_miner / spider_mites | 0 | — |

**Interpretation — this is a cross-domain result and it is bad, on purpose.**
v7 was trained on `cropguard-corpus-claude`, whose lesion masks are *rectangles
equal to the detection boxes* and whose severity is a constant 1.0 for 99.8% of
images (`docs/V7_DATA_AUDIT_2026-10-11.md`). A model trained on that learned
"the lesion is most of the leaf": on this split it predicts lesion over ~60% of
the frame where the real annotation covers ~1% of it (per-image check:
`seg_mean` 0.57–0.69 vs `gt_lesion` 0.005–0.012). Hence mIoU ≈ 0.01 and
severity MAE 0.86.

Classification is the part that survives: 0.517 top-1, with early/late blight,
septoria and leaf-mold all ≥ 0.55 F1 and bacterial spot collapsing (0.15).

This is the honest number to report. It says the segmentation and severity
heads are **not** validated by this checkpoint, and that fixing them requires
retraining on `cropguard_v7_split` — which the repaired derive now makes
possible.

## 2. PlantDoc test (79 tomato images, 8 classes)

`model/training/eval_plantdoc.py --ckpt best_stage5_calibrated.pt`

PlantDoc carries no masks, boxes or severity, so only classification is
measurable; non-tomato folders are skipped (19 of them). Mapping is explicit in
the script (`PLANTDOC_TOMATO`), verified against the dataset's own folder list,
and an unmapped tomato folder is a hard error, not a silent skip.

PlantDoc is in-the-wild field imagery — a genuinely different domain — so 0.43

## 3. Temperature scaling + "unsure" threshold

`model/training/calibrate_abstention.py`, fitted on the **val** split (136
images), never on test:

| | value |
|---|---|
| fitted temperature | **1.4618** |
| prob threshold at 5% abstain target | 0.231 |
| energy threshold | −4.742 |

Written into `model/weights/v7/best_stage5_calibrated.pt` (the `abstain.temperature`
buffer; the original `best_stage5.pt` is untouched). The serving module
`app/api/model_v7_serving.py` already mirrors `AbstainHead`, so loading the
calibrated checkpoint is all that is needed to deploy it.

Effect (PlantDoc test):

| | uncalibrated | calibrated |
|---|---|---|
| temperature | 1.0 | 1.46 |
| unsure rate (thresh 0.231) | — | 6.3% |
| top-1 | 0.430 | 0.430 |
| top-1 on confident subset | — | **0.460** |

Abstaining on the least-confident 6.3% buys +2.9 points of accuracy on PlantDoc.
On PlantSeg it does **not** help (0.513 confident vs 0.517 all) — reported as
such rather than hidden.

## 4. On-device latency

Not yet measured — **cannot** be measured from this host, and a Kaggle CPU/T4
number would be meaningless (static INT8 is faster than FP32 on a Ryzen but
slower on a T4). A harness that runs the shipped ONNX **inside the phone's
browser** is provided:

```
cd mobile/bench && python3 -m http.server 8000
# phone on the same Wi-Fi: http://<laptop-ip>:8000/phone_bench.html
```

It times FP32 / INT8-static / INT8-dynamic (warmup + 30/50/100 runs, median /
p90), and `bench_onnx_phone.py` does the same natively under Termux. See
`mobile/bench/README.md` for the results table to fill in.

## Reproduce

```bash
# derive spot-check (the gate)
python3 data_pipeline/scripts/spotcheck_derive.py \
    --root ~/tmp/cgpack/cropguard_v7_split --split test --n 50 --out ~/tmp/cgcheck

# repair leaf masks in a derived split (idempotent)
python3 data_pipeline/scripts/releaf_split.py \
    --root ~/tmp/cgpack/cropguard_v7_split --splits val,train,test

# calibration (val)
python3 model/training/calibrate_abstention.py \
    --ckpt model/weights/v7/best_stage5_calibrated.pt \
    --root ~/tmp/cgpack/cropguard_v7_split --split val --write

# evals
python3 model/training/eval_tta.py --arch v7 --root ~/tmp/cgpack/cropguard_v7_split \
    --split test --ckpt model/weights/v7/best_stage5_calibrated.pt \
    --unsure-thresh 0.231 --out model/weights/v7/metrics_plantseg_test_v7.json
python3 model/training/eval_plantdoc.py \
    --ckpt model/weights/v7/best_stage5_calibrated.pt \
    --root ~/tmp/plantdoc/test --unsure-thresh 0.231 \
    --out model/weights/v7/metrics_plantdoc_v7.json
```

Artifacts: `model/weights/v7/metrics_plantseg_test_v7.json`,
`model/weights/v7/metrics_plantdoc_v7.json`.
